# JobProof「能力证据工坊」产品需求文档（PRD）

版本：v0.1

状态：待用户确认，确认后进入编码

## 1. 产品概述

### 1.1 产品定位

JobProof 面向没有实习经验或实习较少的大学生，帮助他们把目标岗位 JD 转化为：

```text
岗位要求 → 个人能力差距 → 7/14 天微项目 → 可验证成果 → 求职表达
```

第一版聚焦一个窄场景：**大二/大三学生申请产品或运营实习**。

### 1.2 核心承诺

用户注册时先确认个人能力和已有证据；之后可以按能力匹配 JD，也可以粘贴目标 JD，系统给出缺口和下一步微项目。

### 1.3 不做什么

- 不做新的综合招聘平台
- 不做海量岗位抓取和自动投递
- 不做泛化职业性格测评
- 不替用户编造实习、项目和数据
- 不在 MVP 阶段覆盖所有专业和岗位

## 2. 用户与场景

### 2.1 核心用户画像

| 用户 | 特征 | 主要任务 | 关键障碍 |
|---|---|---|---|
| 探索型学生 | 大一/大二，方向不确定 | 判断自己适合什么岗位 | 看不懂岗位真实工作内容 |
| 补强型学生 | 大二/大三，目标大致明确 | 在投递前补能力 | 不知道做什么项目才算数 |
| 转化型学生 | 有课程/社团/兼职经历 | 把经历写进简历和面试 | 只有流水账，没有证据和结果 |

首版只服务“补强型学生”，另外两类作为可兼容场景。

### 2.2 用户故事

- 作为一个没有实习经历的大二学生，我希望知道某份 JD 要求的能力，避免盲目投递。
- 作为一个目标做产品运营的学生，我希望得到一个两周内能完成的真实练习，而不是泛泛的学习建议。
- 作为一个做过社团项目的学生，我希望把真实经历转换成简历 bullet、作品集案例和面试故事。
- 作为一个不确定自己水平的学生，我希望系统允许我标记“接触过”和“暂无证据”，而不是迫使我夸大能力。

## 3. 产品目标与成功标准

### 3.1 MVP 目标

1. 让用户在 3 分钟内完成基础能力画像。
2. 让用户从一份 JD 得到 3–5 张有原文依据的能力卡。
3. 让用户得到一个包含交付物和验收标准的 7/14 天微项目。
4. 让用户提交成果后，生成可编辑的简历、作品集和面试表达。

### 3.2 MVP 成功标准

- JD 分析完成率 ≥ 70%
- 能力画像完成率 ≥ 70%
- 计划创建率 ≥ 50%
- 至少一项成果成功转化为求职表达的比例 ≥ 60%
- 用户对“我知道下一步做什么”的评分 ≥ 4/5

## 4. 核心产品流程

```text
注册
  ↓
基本背景与求职约束
  ↓
个人能力确认表
  ↓
能力画像
  ├─ 按我的能力找 JD
  └─ 我已有目标 JD
          ↓
      能力差距分析
          ↓
      7/14 天微项目
          ↓
      证据提交与完整度检查
          ↓
      简历 / 作品集 / 面试表达
```

## 5. 功能需求

### 5.1 注册与个人能力确认（P0）

#### 基本背景字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| 年级 | 单选 | 是 | 大一/大二/大三/大四/研究生 |
| 专业 | 文本 | 是 | 支持推荐词 |
| 目标城市 | 多选 | 是 | 城市/远程 |
| 每周可投入时间 | 单选 | 是 | 3h/5h/8h+ |
| 求职阶段 | 单选 | 是 | 探索/准备投递/已有实习 |
| 期望岗位族 | 多选 | 否 | 产品/运营/数据/设计/研发 |

#### 能力确认字段

首版产品/运营能力包包含：信息搜集、用户访谈、竞品分析、数据整理、内容策划、项目推进、表达与汇报、工具使用。

每项能力记录：

- 自评等级：不了解 / 接触过 / 能独立完成小任务 / 能交付完整结果
- 证据来源：课程作业 / 社团或兼职 / 个人项目 / 实习 / 暂无
- 事实描述：20 字以内，描述做过什么
- 结果描述：可选，允许暂无数字
- 兴趣偏好：喜欢 / 可以尝试 / 不想做

#### 交互要求

- 注册页不超过 10 个必填字段。
- 用户可以跳过事实细节，之后在个人中心补充。
- “自评等级”和“证据强度”分开展示。
- 没有证据的能力显示“待验证”，不能被系统描述为已掌握。
- 注册完成后必须生成一张可编辑的能力确认表。

### 5.2 个人中心（P0）

展示：

- 基本资料和求职偏好
- 能力画像完成度
- 各项能力的自评分和证据强度
- 最近的能力证据
- 当前微项目及任务进度
- 推荐 JD 与匹配解释

核心动作：编辑能力、补充证据、新建能力计划、查看匹配 JD。

### 5.3 JD 输入与分析（P0）

输入方式：

- 粘贴 JD 文本
- 后续支持 URL 或文件导入（P1）

输出：

- 岗位标题、公司、地点和工作摘要
- 3–5 个能力单元
- 必须能力与加分能力
- 每项能力对应的 JD 原文
- 用户已有证据、待验证缺口和硬性风险

验收标准：每张能力卡必须能展开查看对应原文，禁止无来源的能力推断直接展示为事实。

### 5.4 按能力匹配 JD（P0）

展示 5–10 个推荐岗位，每个岗位包含：

- 匹配分
- 3 个匹配点
- 2 个能力缺口
- 1 个推荐先完成的微项目
- 城市、年级、时间等硬性约束风险

匹配评分：

```text
总分 = 45% 能力覆盖度
     + 25% 证据强度
     + 15% 兴趣与岗位偏好
     + 15% 基本约束匹配
```

### 5.5 微项目计划（P0）

用户选择 7 天或 14 天计划后，系统生成：

- 项目目标
- 每日/每周任务
- 输入模板与参考示例
- 交付物清单
- 验收标准
- 需要补充的事实或数据

计划必须可在用户填写的每周时间内完成，不输出“学习完某门课程”这种不可验收任务。

### 5.6 证据工作台（P0）

支持提交：文字、链接、文件、数字结果、反思。

系统检查五项完整度：

1. 背景/问题
2. 个人任务
3. 具体动作
4. 结果或数字
5. 反思/下一步

缺少数字时可以继续提交，但必须标记“待补充”，不得自动填充虚构数字。

### 5.7 求职表达生成（P0）

支持三种输出：

- 简历 bullet：动词 + 方法/工具 + 结果
- 作品集案例：背景、过程、结果、反思
- 面试故事：STAR 结构 + 3 个追问

所有输出必须显示来源证据，用户确认后才保存为正式版本。

## 6. 页面清单

| 页面 | 优先级 | 关键动作 |
|---|---:|---|
| 注册/能力确认 | P0 | 填背景、确认能力、补事实 |
| 个人中心 | P0 | 查看画像、证据、任务和 JD |
| JD 分析结果 | P0 | 查看能力卡和差距 |
| 微项目详情 | P0 | 查看任务、提交成果 |
| 证据详情 | P0 | 补齐事实、查看完整度 |
| 求职表达 | P0 | 生成并编辑三种表达 |
| 设置与隐私 | P1 | 删除数据、分享设置 |

## 7. 产品规则

1. 能力判断必须区分“自评”和“证据”。
2. AI 生成内容必须可追溯到 JD 原文或用户提交的事实。
3. 缺少信息时显示“待补充”，不编造。
4. 所有生成内容可编辑、可撤销。
5. 首版只做产品/运营能力包，验证后再扩展岗位族。

## 8. 风险与应对

| 风险 | 应对 |
|---|---|
| 注册表过长导致流失 | 首屏只收关键字段；事实细节可后补 |
| 用户高估能力 | 自评和证据分开；无证据自动进入验证任务 |
| AI 编造项目数据 | 结构化输入、事实来源回链、缺失字段不生成数字 |
| 微项目内容空泛 | 首版人工打磨产品/运营任务模板，模型只做个性化调整 |
| 推荐 JD 不合适 | 展示匹配理由和硬性风险，允许用户反馈“不适合” |

## 9. MVP 交付判定

用户从注册开始，可以在一次完整流程中：

1. 完成能力确认；
2. 获得能力画像；
3. 选择或粘贴 JD；
4. 获得能力差距；
5. 创建微项目；
6. 提交一项成果；
7. 得到一份可编辑的简历 bullet、作品集案例和面试追问卡。

以上 7 步跑通后，才进入下一阶段的岗位扩展、导师协作和数据沉淀。

## 10. 待确认事项

- 首版是否只开放产品/运营两个岗位族？（建议：是）
- 是否允许用户跳过能力确认直接粘贴 JD？（建议：允许，但先完成基础背景）
- 首版是否支持文件上传？（建议：先支持文本和链接，文件作为 P1）
- 首版是否需要真实岗位数据？（建议：先用示例 JD 和人工录入岗位验证闭环）

# JobProof「能力证据工坊」技术设计文档

版本：v0.1

状态：待产品需求确认，确认后进入编码

## 1. 技术目标

在不引入复杂微服务的前提下，支持以下端到端流程：

```text
用户注册 → 能力画像 → JD 分析 → 能力匹配 → 微项目 → 证据 → 求职表达
```

技术重点：

- 结构化 AI 输出，而不是自由文本拼接；
- 所有推荐和生成结果可回溯；
- 用户事实与 AI 推断分离；
- MVP 可单体部署，后续可拆分模型和检索服务。

## 2. 推荐技术栈

### 前端与应用层

- Next.js App Router
- TypeScript
- React Hook Form：表单状态与校验
- Zod：前后端共享 Schema
- Tailwind CSS 或现有设计系统

### 数据与基础设施

- PostgreSQL：用户、能力、JD、计划和证据
- Supabase Auth：邮箱/魔法链接登录
- Supabase Storage：用户主动上传的证据文件
- 部署：Vercel 或同类 Node.js 平台

### AI 层

- LLM Provider Adapter：隔离具体模型供应商
- Structured Output / JSON Schema：约束模型输出
- Prompt Registry：提示词版本化
- 可选 Redis：限流、异步任务和缓存（P1）

## 6. AI 编排设计

### 6.1 JD 抽取器

输入：清洗后的 JD 文本。

输出：岗位摘要、能力单元、重要度、原文引用、置信度、假设。

约束：

- 只允许从 JD 文本抽取能力；
- 每项能力必须带 `jdQuote`；
- 不能把公司宣传语直接当成能力要求；
- 输出不符合 Schema 时自动重试一次。

### 6.2 匹配解释器

计算逻辑放在服务端，不交给模型决定分数：

```text
score = coverage * 0.45
      + evidence * 0.25
      + preference * 0.15
      + constraints * 0.15
```

模型只负责把结构化结果转成可读解释；解释必须引用匹配数据和缺口数据。

### 6.3 微项目生成器

输入：目标 JD 能力卡、用户画像、每周可投入时间、7/14 天选项。

输出：目标、任务、交付物、验收标准、参考模板。

硬性规则：

- 每项任务有明确动词和交付物；
- 任务总时长不超过用户可投入时间；
- 不生成只有“学习/了解/熟悉”的任务；
- 至少有一项可上传或可链接的成果。

### 6.4 求职表达生成器

输入：已确认的证据 ID。

输出：简历、作品集、面试三种格式。

硬性规则：

- 只能使用证据中存在的事实；
- 没有数字时使用“待补充”占位；
- 生成内容附带 `sourceEvidenceIds`；
- 生成结果默认是草稿，用户确认后才变为正式版本。

## 8. 权限与安全

- 所有业务表使用 `user_id` 或画像关系做行级权限控制。
- 用户上传文件默认私有；分享时生成限时签名 URL。
- JD 中的邮箱、手机号、身份证号等敏感信息在发送给模型前脱敏。
- 不在日志中记录完整 JD、简历和证据原文；只记录请求 ID、模型版本和错误摘要。
- 用户可以删除个人画像、JD、证据和生成结果。
- AI 输出显式标注“AI 草稿”。

## 9. 观测与错误处理

记录：

- 请求耗时、模型、提示词版本、Schema 校验结果；
- 失败类型：超时、限流、解析失败、内容为空；
- 用户是否编辑了生成结果；
- 用户是否完成计划和提交证据。

策略：

- Schema 失败：自动重试一次；
- 模型不可用：返回可编辑模板，不阻塞用户；
- 重复 JD：按文本哈希缓存分析结果；
- 文件解析失败：提示用户粘贴文本继续。

## 10. 实现顺序

### Phase 1：本地可演示

- 静态能力确认表
- 个人中心
- 示例 JD 与示例能力卡
- 示例微项目和三种表达

### Phase 2：真实数据闭环

- Supabase Auth 与数据库
- 能力画像保存/编辑

### Phase 3：AI 与可信度

- Schema 约束的 JD 抽取
- 微项目生成
- 证据完整度检查
- 追溯式表达生成
- 错误重试和成本控制

### Phase 4：发布前加固

- 权限测试
- 敏感信息脱敏
- 删除数据流程
- 移动端适配
- 埋点与验收指标看板

## 11. 测试策略

### 单元测试

- 能力等级和证据等级枚举校验
- 匹配分计算
- 任务时长约束
- 表达来源 ID 完整性

### 集成测试

- 注册能力画像保存与读取
- JD 分析结果入库
- 计划生成到任务创建
- 证据提交到表达生成

### AI 回归测试

准备至少 20 份人工标注 JD，检查：

- 能力抽取准确性
- 原文引用覆盖率
- 是否出现无来源技能
- 是否生成虚构数字
- 生成计划是否可在时间约束内完成

## 12. 技术验收标准

- 新用户可完成注册并保存能力画像。
- 用户可以编辑任一能力的自评、证据和兴趣。
- 一份 JD 分析结果在 60 秒内返回，或降级为可编辑模板。
- 每张能力卡有 JD 原文引用。
- 匹配分由服务端确定，并能展示分项分数。
- 微项目任务均包含交付物和验收标准。
- 表达结果能追溯到证据 ID，不能凭空添加事实。
- 用户只能访问自己的画像、JD、计划、证据和表达。

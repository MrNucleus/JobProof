# JobProof v0.3：云端数据基础

本批实现 Supabase 的服务端连接、核心表结构、Row Level Security、邮箱 Magic Link 登录，以及能力画像的显式双向同步。没有配置 Supabase 时，现有 localStorage 流程继续工作，公网演示不会被强制切换到云端。

## 配置顺序

1. 在 Supabase 创建项目。
2. 在 SQL Editor 执行 `supabase/migrations/202609140001_jobproof_v03.sql`。
3. 在 Netlify 添加以下变量：

```text
NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<publishable-anon-key>
```

只配置 publishable/anon key，不要把 service role key 放入前端、Git 或普通环境变量。

## 当前 API

```text
GET /api/profile
PUT /api/profile
GET /api/auth/supabase/me
POST /api/auth/supabase/magic-link
GET /api/auth/supabase/callback
POST /api/auth/supabase/logout
```

接口要求已有 Supabase 登录会话。未配置云端时返回 `503`，未登录时返回 `401`；这两种情况都不会影响当前 localStorage 页面。

`PUT /api/profile` 接受当前项目的 `UserProfile` 对象，也兼容 `{ "profile": UserProfile }` 包装形式。服务端会在 `profiles` 和 `profile_competencies` 中使用当前登录用户写入，并由 RLS 限制只能访问本人数据。

## 页面交互

`/account` 会显示独立的 JobProof 云端账号区域。用户登录后可以对比“此设备”和“云端”两个画像版本，并明确选择：

- 上传此设备画像；
- 下载云端画像；
- 两个版本冲突时选择保留哪一份。

系统不会在登录后自动覆盖任何画像。知乎 OAuth 只用于知乎用户信息和公开创作，Supabase 登录只用于 JobProof 自有数据，两套身份彼此独立。

## 本批未开启

- JD、计划、证据和表达的云端 Repository；
- 私有文件 Storage。

这些功能将在画像 API 验证通过后分批接入，避免云端配置缺失时影响公网演示。

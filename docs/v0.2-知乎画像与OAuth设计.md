# v0.2 知乎画像与 OAuth 设计

## 1. 目标

在不削弱“JD → 微项目 → 证据”核心闭环的前提下，接入知乎 OAuth：

- 用户可以使用知乎登录。
- 右上角展示知乎头像和昵称。
- 用户中心展示基础信息、公开创作和公开关注列表。
- 用户明确同意后，使用知乎公开数据辅助生成兴趣与岗位方向参考。
- 用户填写的问卷始终是人物画像的主要依据。

## 2. 数据边界

当前开放接口支持授权用户基础信息、公开创作列表和关注列表，不提供用户完整浏览历史。因此产品文案统一使用“知乎公开行为参考”，不宣称“分析完整使用历史”。

允许使用的信号：

- 创作标题、摘要、内容类型和时间。
- 公开关注用户的名称、简介和关注者数量。
- 用户主动填写的求职目标、能力自评和兴趣问卷。

禁止推断或展示：

- 完整浏览轨迹、搜索历史或未授权数据。
- 心理健康、政治立场、性取向、收入等敏感属性。
- 仅凭关注或阅读某个主题就认定用户具备对应职业能力。

## 3. OAuth 流程

```text
点击知乎登录
  → 服务端生成短时 state
  → 跳转知乎授权页
  → 回调校验 state
  → 服务端用 authorization_code 换 OAuth Token
  → 服务端请求 /user 获取基础信息
  → 创建 HttpOnly 应用会话
  → 右上角显示头像和昵称
```

安全要求：

- App Key、Access Secret、OAuth Token 只存在服务端环境变量或服务端会话。
- 浏览器只持有随机应用会话标识，不接触 OAuth Token。
- `state` 必须随机、短时有效，并在回调中校验。
- 登录授权不等于画像分析授权；画像分析需要独立的用户确认。
- 用户退出、Token 失效或取消授权后，停止访问知乎数据，不切换到其他账号。

## 4. 用户中心

页面 `/account` 包含三块：

1. 用户基础信息：头像、昵称、简介和知乎主页链接。
2. 关注的人：卡片列表，支持点击加载更多。
3. 创作信息：回答、文章、视频、想法和问题，支持点击加载更多。

分页必须原样使用知乎响应中的 `Paging.NextOffset`，不能根据当前条数自行计算偏移量。接口错误、空列表和 Token 失效都要显示可理解的状态。

## 5. 画像融合算法

画像按“兴趣主题、表达偏好、岗位方向、能力证据”分维度计算，不生成一个不可解释的单一人格分数。

### 默认权重

问卷结果是用户直接表达，默认占最终画像的 70%；知乎公开数据经 AI 提炼后仅作为参考，占 30%：

```text
最终画像分 = 问卷结果 × 70% + 知乎 AI 参考 × 30%
```

能力事实例外：只有用户主动提交的项目、成果、数据或链接才能进入“已具备能力”，知乎数据不能直接变成能力证据。

### 动态权重

```text
AI 参考权重 = 30% × 数据置信度 × 新鲜度系数
问卷权重 = 1 - AI 参考权重
```

约束：

- 未授权或冷启动：知乎权重为 0%。
- 少量或单一类型数据：知乎权重最高 15%。
- 至少 5 条公开创作或 10 个以上关注主题，且跨时间信号一致：知乎权重最高 30%。
- 用户修改或锁定某项画像后，该项由用户结果占 100%。
- 问卷与 AI 参考冲突时，同时展示两者，不自动制造一个精确但不可解释的折中结论。

### 画像信号结构

```ts
interface ProfileSignal {
  dimension: "interest" | "expression" | "role_preference";
  statement: string;
  source: "questionnaire" | "zhihu_ai_reference";
  sourceIds: string[];
  confidence: number;
  observedAt: string;
  status: "suggested" | "confirmed" | "dismissed" | "locked";
}
```

只有 `confirmed` 或 `locked` 的信号可以影响微项目推荐；`suggested` 只能作为待确认提示。

## 6. AI 处理流程

```text
授权并确认画像分析
  → 拉取最小分页数据
  → 清洗标题、摘要和关注主题
  → 主题聚类与时间衰减
  → 生成带来源的 AI 参考
  → 与问卷按动态权重合并
  → 用户确认、修改、隐藏或锁定
```

AI 输出必须包含：

- 画像维度和参考结论。
- 来源内容 ID 和时间范围。
- 置信度与使用的权重。
- “AI 参考”标记。
- 可执行的确认问题，而不是未经确认的事实陈述。

## 7. v0.2 验收标准

- OAuth 登录成功后，右上角显示头像和昵称。
- 用户中心可以展示基础信息，并在 Mock 数据下验证关注和创作分页。
- 用户可以单独拒绝画像分析，拒绝后仍可使用 JD 分析和微项目功能。
- 未授权、接口失败或数据为空时，问卷画像和核心求职流程仍可用。
- 默认融合比例为问卷 70%、知乎 AI 参考 30%，并在界面上可解释。
- 用户锁定的画像不会被 AI 覆盖。
- 每条画像建议都有来源、置信度和确认状态。
- 敏感凭证、OAuth Token 和完整用户隐私不进入前端、URL、日志或 Git。

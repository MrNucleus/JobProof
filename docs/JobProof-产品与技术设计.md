# JobProof「能力证据工坊」

产品与技术设计 v0.1 · 黑客松 MVP

## 1. 产品结论

JobProof 不做新的招聘信息聚合器，而是做一层“岗位要求 → 能力训练 → 可展示证据”的转化工具。

核心承诺：

> 用户粘贴一份目标岗位 JD，15 分钟内得到一份适合自己当前水平的 7/14 天微项目；完成后，系统把成果整理成简历 bullet、作品集案例和面试故事。

首个目标用户是：**大二/大三、零实习或实习很少、准备申请第一份产品/运营实习的学生**。

## 2. 用户问题与产品假设

### 2.1 问题链

1. 学生看到很多岗位，但不会判断岗位每天真实做什么。
2. 学生能读懂“需要数据分析/用户调研/内容策划”，却不知道自己差多少。
3. 学生知道要补能力，但不知道做什么练习才算“像工作”。
4. 完成课程作业或小项目后，无法转成有结果、有证据的求职表达。

### 2.2 产品假设

- 如果把一份 JD 拆成少量能力单元，学生会更容易选择一个明确目标。
- 如果任务有时间盒、输入模板和验收标准，学生更可能完成，而不是停在“学习建议”。
- 如果成果可以直接转成简历、作品集和面试故事，学生会感知到即时价值并愿意持续使用。

## 3. MVP 用户流程

```text
输入 JD → 识别岗位任务 → 自评已有证据 → 生成能力差距卡
       → 选择 7/14 天微项目 → 每日/每周提交成果
       → 证据审核与补强 → 输出简历 + 作品集 + 面试故事
```

### 3.1 页面与功能

| 页面 | 用户动作 | MVP 输出 |
|---|---|---|
| 01 JD 输入 | 粘贴 JD、选择目标方向和可投入时间 | 解析进度与岗位摘要 |
| 02 能力差距 | 确认任务、填写“做过/没做过/不确定” | 3–5 张能力卡、优先级与原因 |
| 03 微项目计划 | 选择 7 天或 14 天计划 | 任务清单、模板、验收标准 |
| 04 证据工作台 | 上传链接/文件、填写结果数字与反思 | 证据完整度、缺口提醒 |
| 05 求职表达 | 选择简历/作品集/面试 | STAR bullet、案例页、追问卡 |

### 3.2 能力卡字段

- 能力名称：如用户访谈、竞品分析、Excel 数据整理
- JD 原文证据：保留对应句子，避免 AI“凭空发挥”
- 重要度：必须 / 加分 / 可选
- 用户现状：已有证据 / 部分掌握 / 尚无证据
- 建议验证任务：一项可在 7–14 天完成的微项目
- 验收标准：数量、质量、格式、可解释性
- 生成物：表格、分析页、原型、复盘或演示视频

### 3.3 微项目示例

目标岗位：产品运营实习生

- 能力单元：用户调研、竞品分析、数据整理、内容策划
- 项目题目：为校园二手交易小程序做一次竞品与用户需求分析
- 7 天交付：访谈 5 人、分析 5 个竞品、整理 3 个关键指标、提出 2 条可执行建议
- 验收标准：有原始记录、有分析依据、有优先级、有下一步动作
- 最终证据：1 页结论、1 份数据表、1 段 90 秒讲解

## 4. 产品边界

### MVP 必做

- 支持粘贴 JD 并结构化拆解
- 支持学生自评与补充已有经历
- 生成一个可执行的 7/14 天微项目
- 记录成果并生成三种求职表达
- 每个 AI 结论都能回链到 JD 原文或用户输入

### MVP 暂不做

- 全网职位抓取、自动投递、企业端招聘
- 泛化的职业性格测评
- 覆盖所有专业的任务库
- 自动判定作品“优秀/不优秀”
- 付费课程、导师社区和复杂社交功能

原则：先证明“学生真的能把 JD 变成一份证据”，再扩展岗位和社区。

## 5. 技术方案

### 5.1 推荐架构

黑客松优先采用单体全栈，降低联调成本：

```text
Next.js App Router + TypeScript
        ├─ Server Actions / Route Handlers
        ├─ PostgreSQL（Supabase）
        ├─ 对象存储（成果文件）
        ├─ LLM Adapter（结构化 JSON 输出）
        └─ 可选：向量检索（第二阶段）
```

推荐理由：一个仓库即可完成页面、接口和部署；Supabase 提供登录、数据库和文件存储；模型供应商通过 Adapter 隔离，后续可替换。

### 5.2 AI 处理管线

不要让模型直接“自由发挥”，采用四段式：

1. **清洗**：去除 JD HTML、重复福利和无关公司宣传语。
2. **抽取**：模型以 JSON 输出岗位任务、技能、证据句和重要度。
3. **约束生成**：根据用户时间、年级、已有经历生成微项目；强制包含时间盒、交付物和验收标准。
4. **转化**：只使用用户提交的事实生成 STAR；缺数字时输出“待补充”而不是编造。

模型输出必须经过 Zod/JSON Schema 校验；失败时重试一次，仍失败则返回可编辑的基础模板。

### 5.3 API 草案

```text
POST /api/jd/analyze
输入：{ jdText, targetRole?, weeklyHours?, userContext? }
输出：{ jobSummary, competencies[], assumptions[] }

POST /api/plans
输入：{ jobId, competencyIds[], durationDays: 7 | 14 }
输出：{ planId, tasks[], deliverables[], rubric[] }

POST /api/evidence
输入：{ planId, taskId, text?, url?, fileId?, metrics? }
输出：{ evidenceId, completeness, missingFields[] }

POST /api/expressions
输入：{ evidenceIds[], format: 'resume' | 'portfolio' | 'interview' }
输出：{ draft, sourceEvidence[], followUps[] }
```

### 5.4 数据模型

```sql
users(id, email, year, major, target_role, created_at)
jobs(id, user_id, raw_text, title, company, created_at)
competencies(id, job_id, name, importance, jd_quote, status, priority)
plans(id, job_id, duration_days, goal, status, created_at)
tasks(id, plan_id, title, instructions, due_day, deliverable, rubric_json, status)
evidence(id, task_id, text, url, file_path, metrics_json, reflection, created_at)
expressions(id, evidence_ids_json, format, content, source_ids_json, created_at)
```

关键约束：

- `jd_quote` 必须保存原文片段，支持解释“为什么推荐这个能力”。
- `expressions.source_ids_json` 必须记录生成所依据的证据，便于用户核对。
- 文件只保存用户主动上传的成果；默认私有，分享时生成临时链接。

### 5.5 前端状态与交互

- 使用步骤状态：`draft → analyzed → plan_created → in_progress → evidence_ready → exported`
- AI 请求显示“正在分析哪一步”，避免只有无限转圈。
- 所有生成结果可编辑；用户确认后才写入正式版本。
- 页面右侧固定显示“证据完整度”：事实、动作、结果、数字、反思五项。

## 6. 质量、安全与可信度

- 不编造经历：缺失事实统一显示“待补充”。
- 对 JD 做敏感信息过滤，避免把手机号、身份证、邮箱送入模型。
- 用户成果默认不公开；分享页需显式开启并可随时撤回。
- 对生成内容标注“AI 草稿”，最终由用户确认。
- 记录模型版本、提示词版本和输入摘要，便于复盘错误。

## 7. 验收指标

### 黑客松 Demo 指标

- 1 份 JD 在 60 秒内完成结构化拆解
- 至少生成 3 张能力卡，且每张有 JD 原文依据
- 生成的计划包含明确交付物和验收标准
- 上传一份成果后，能生成简历/作品集/面试三种表达

### 后续真实用户指标

- JD 分析完成率 ≥ 70%
- 计划创建率 ≥ 50%
- 7 天计划完成率 ≥ 30%
- 至少一项成果被转成可用求职表达的比例 ≥ 60%
- 用户对“我知道下一步做什么”的评分 ≥ 4/5

## 8. 黑客松实现顺序

### 第 1 阶段：可演示骨架

- 静态页面与示例 JD
- 结构化能力卡 JSON
- 计划页与示例任务
- 结果页三种表达切换

### 第 2 阶段：接入真实 AI

- JD 抽取 Prompt + Schema 校验
- 计划生成 Prompt
- STAR 转化 Prompt
- 错误重试与人工编辑

### 第 3 阶段：补可信度与完成感

- 证据上传
- 完整度评分
- 来源回链
- 导出 Markdown/PDF 或分享页

## 9. 现场演示脚本（3 分钟）

1. 展示一个“产品运营实习生” JD，指出学生看得懂关键词但不知道怎么补能力。
2. 粘贴 JD，展示 4 张能力卡，并点击查看每张卡对应的原文。
3. 选择“7 天计划”，展示任务、模板与验收标准。
4. 上传一份竞品分析结果，补充“分析 5 个竞品、提出 2 条建议”。
5. 一键生成简历 bullet、作品集案例和面试追问卡。
6. 用一句话收尾：**我们不替学生海投，而是帮他在投递前做出能证明能力的证据。**

## 10. 关键决策

第一版只服务一个窄场景：**零实习大学生申请产品/运营实习**。这样可以把任务模板、验收标准和示例做深，形成比“通用 AI 求职助手”更可信的体验。后续再扩展到数据分析、设计、研发等岗位。
